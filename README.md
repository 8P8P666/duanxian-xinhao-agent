# 短线共振信号智能体

**币安 Agent 参赛作品 · 方向：数据分析**

同时计算 MACD、RSI、KDJ、BOLL 四个技术指标，判断它们是否在同一方向上形成共振，
并对容易失效的单一指标信号做二次过滤，最后输出四档市场结构评级。

---

## 一、解决什么问题

技术指标最常见的用法是「看到金叉就行动」，但单一指标在震荡行情中会反复交叉，
产生大量无效信号。本项目的思路不是再造一个指标，而是：

1. **让四个指标同时说话** —— 只有当多个指标方向一致时，才认为是较强信号；
2. **给信号做二次过滤** —— 检查成交量、中期趋势、极端位置、波动状态、K线确认，
   把「看起来像信号」的情况识别出来并主动降级。

换句话说，它更重要的能力是 **过滤掉不该行动的时候**，而不是制造更多交易理由。

---

## 二、核心功能

### 功能一：多指标共振判定

四个指标各自给出方向（偏多 / 偏空 / 中性），按权重汇总成综合评分：

| 指标 | 参数 | 权重 | 方向判定依据 |
|---|---|---|---|
| MACD | 12 / 26 / 9 | 1.2 | DIF 与 DEA 的相对位置，并识别金叉 / 死叉 |
| RSI | 14（Wilder 平滑） | 0.9 | 55 以上偏多、45 以下偏空，并标注超买超卖 |
| KDJ | 9 / 3 / 3 | 1.0 | K 线与 D 线的相对位置，并识别金叉 / 死叉 |
| BOLL | 20 周期 / 2 倍标准差 | 1.0 | 收盘价相对中轨的位置，并计算通道位置与带宽 |

综合评分区间为 -100 到 +100，映射为四档评级：

| 评级 | 评分区间 | 含义 |
|---|---|---|
| 强做多 | ≥ +55 | 多个指标方向一致向上，且通过主要过滤规则 |
| 谨慎做多 | +25 ~ +55 | 偏多指标占多数，但仍有关键条件未满足 |
| 震荡 | -25 ~ +25 | 多空接近，或信号被过滤规则完全削弱 |
| 强做空 | ≤ -25 | 多个指标方向一致向下，且通过主要过滤规则 |

> 说明：评级属于程序化技术信号，用于描述市场结构，不是交易指令。

### 功能二：假信号过滤

六条过滤规则，每条独立判断，触发即按权重扣减信号强度：

| 规则 | 触发条件 | 扣分 | 过滤目的 |
|---|---|---|---|
| 孤立信号检查 | 四个指标中只有 1 个给出方向 | -22 | 排除典型的单一指标信号 |
| 量能确认 | 已收线K线成交量低于 20 根均量的 80% | -14 | 排除缺少资金参与的价格变化 |
| 趋势一致性 | 信号方向与 EMA20 / EMA50 中期趋势相反 | -16 | 排除逆势的短线反弹或回落 |
| 极端值风险 | 偏多时 RSI ≥ 75 或价格超出布林上轨；偏空时反向同理 | -20 | 排除追涨杀跌位置 |
| 通道收窄检查 | 布林带宽处于近 60 根的偏低水平 | -12 | 波动压缩时方向尚未选择 |
| K线方向确认 | 最新K线方向与信号方向不一致 | -8 | 要求信号得到K线配合 |

**两条重要的计算约束：**

1. 过滤只能**削弱**信号强度，不能加强，也不能把方向反转。因此不会出现
   「因为触发了降级规则，评级反而变得更强」这种自相矛盾的结果。
2. 成交量比较**只使用已经收线的K线**。正在形成中的K线成交量天然不完整，
   如果用它去比较，会让每根K线都被误判成缩量。

## 三、数据来源

| 项目 | 说明 |
|---|---|
| 主数据源 | **综合交易平台公开行情接口**（现货 / USDT 永续合约） |
| 备用与增强数据源 | **链上永续平台公开行情接口**（链上永续合约） |
| 跨平台对照 | 同一币种在两个平台的公开行情价格、持仓量、资金费率同时抓取并计算价差 |
| 是否需要密钥 | 不需要。两个接口都是公开行情接口 |
| 是否涉及交易 | 不涉及。不接入交易权限，不保存私钥，不执行任何下单 |

**资金费率口径处理：** 链上永续平台资金费率按 1 小时结算，综合交易平台按 8 小时结算，
两者不能直接比较。页面统一换算成**年化资金费率**后再展示，同时保留各自的原始结算周期标注。

**数据真实性原则：** 页面只展示接口真实返回的数据。接口失败时显示明确的失败原因，
不会用任何演示数据或固定数值顶替，也不会把演示数据描述成实时数据。

## 四、页面结构

采用多列流式仪表盘布局，自上而下分为：

1. **顶部品牌栏** —— 币安 Agent 参赛作品 · 方向：数据分析，右侧显示数据源连接状态
2. **主视觉区** —— 项目名称、宣传语、接入数据源与输出说明，配 Web3 节点网络装饰
3. **分析控制台** —— 数据平台、市场类型、分析币种、分析周期、开始分析
4. **行情摘要卡片** —— 最新价、24 小时涨跌、24 小时成交额、年化资金费率、持仓量、标记价、布林位置、共振评价
5. **共振结论卡片** —— 评级徽章、综合评分条、共振强度、投票明细、过滤扣分、结论说明
6. **假信号过滤结果** —— 六条规则逐条列出通过或触发状态及具体原因
7. **四指标逐项拆解** —— 四张指标卡，各自显示数值、方向与标签
8. **价格结构与布林通道** —— 自绘K线图，含布林三轨、成交量柱与鼠标定位
9. **评级变化轨迹** —— 近 48 根K线的评级色带，用于观察方向判断是否稳定
10. **跨平台真实数据对照** —— 两平台价格、价差、持仓量、年化资金费率
11. **数据来源与计算口径说明**
12. **风险提示**

页面配色为黄色数据分析台风格，加入 BTC 标识、区块链节点连线等 Web3 元素。
按中国习惯，做多与上涨使用红色，做空与下跌使用绿色。

## 五、目录结构

```text
币安作品8p/
├─ index.html                   # 页面结构
├─ styles.css                   # 黄色主题与仪表盘样式
├─ favicon.svg
├─ indicators.js                # MACD / RSI / KDJ / BOLL 计算
├─ signal-engine.js             # 共振判定与假信号过滤
├─ chart.js                     # 自绘K线图表（无外部依赖）
├─ data-direct.js               # 浏览器直连取数（云端函数不可用时兜底）
├─ api-client.js                # 接口调用封装与通道自动选择
├─ app.js                       # 页面主逻辑与渲染
├─ functions/                   # 云端接口代理（Netlify Functions）
│  ├─ _data.cjs                 # 两个平台的行情抓取与统一格式
│  ├─ market.cjs                # /api/market  行情与K线
│  └─ symbols.cjs               # /api/symbols 币种列表
├─ netlify.toml                 # Netlify 构建与路由配置
├─ package.json
├─ dev-server.mjs               # 本地测试服务器
├─ 打包上传文件夹.mjs           # 生成两个可直接拖拽上传的文件夹
└─ 检查上传格式.mjs             # 上传前格式体检（12 项）
```

> **为什么是「扁平结构」**：网页文件全部直接放在仓库根目录，只有一个 `functions/`
> 文件夹。这样在 GitHub 网页版上传时，按 `Ctrl+A` 全选出来的全是文件、不含任何文件夹 ——
> 而 GitHub 网页版上传只认单独的文件，选中文件夹会被忽略。扁平结构让上传一次成功。


前端优先请求 `/api/xxx`，由 Netlify Functions 转发到交易所。
**当页面上没有部署云端函数时**（例如把静态文件直接拖到 Netlify Drop），
`api-client.js` 会自动检测并切换到 `data-direct.js` 的浏览器直连通道，
页面依然能取到真实数据，不会白屏。

两条通道取到的都是交易所公开接口的真实数据，计算口径完全一致
（`_data.cjs` 与 `data-direct.js` 必须保持同步修改）。
页面会在「数据源」一栏如实标注当前使用的是哪条通道。

图表为纯 Canvas 自绘，不加载任何外部图表库，因此不存在 CDN 加载失败导致页面空白的问题。

## 六、本地运行

需要先安装 Node.js（18 或更高版本）。

```bash
cd "D:/币安作品8p"
node dev-server.mjs
```

启动后在浏览器打开：

```text
http://127.0.0.1:8790
```

本地服务器复用了与 Netlify 完全相同的接口代码，所以本地验证通过的行为，部署后一致。

## 七、部署到 Netlify

### 方式一：拖拽上传（快速看效果）

Netlify 的拖拽上传只支持纯静态文件，不会运行云端函数。
为此项目提供了打包脚本，把网页文件整理成一个可以直接拖拽的文件夹：

```bash
cd "D:/币安作品8p"
node 打包上传文件夹.mjs
```

脚本会同时生成两个文件夹：

- `币安作品8p-纯静态上传`（9 个文件）→ 拖到 https://app.netlify.com/drop
- `币安作品8p-GitHub上传`（22 个文件，摊平成一层）→ 拖到 GitHub 网页版

这种方式下页面会自动走浏览器直连通道，数据来源会显示「· 浏览器直连」。

> 注意：每次改完页面代码都要重新执行一次打包脚本，否则上传的还是旧版本。

### 方式二：连接 Git 仓库（推荐用于定稿）

`netlify.toml` 已经配置完成，不需要额外修改：

- 发布目录：`.`（仓库根目录本身就是网站根目录）
- 函数目录：`functions`
- 接口路由：`/api/market`、`/api/symbols` 自动转发到对应的函数

在 Netlify 中新建站点，连接本仓库后直接部署即可，无需填写构建命令。
这种方式下页面走云端接口代理，数据来源会显示「· 云端接口代理」，
并且带有服务端短时缓存。

## 八、风险提示

本页面仅用于数字资产市场风险观测与数据分析，不构成投资建议，不代表任何买卖承诺。
页面中的「强做多」「强做空」等评级是程序化技术信号的计算结果，不等于实际交易建议。
技术指标是对历史价格的统计描述，天然滞后；震荡行情中指标容易反复交叉，趋势末端指标容易钝化。
本页面的过滤规则只能降低部分噪音，无法消除判断误差，行情数据可能存在延迟、缺失或接口波动。

市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标独立判断，
必要时咨询持牌专业机构。过往表现不预示未来收益。
